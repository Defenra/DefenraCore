# Anycast Routing (BETA)

## Что это такое?

Anycast Routing — это новая функция DefenraAgent, которая позволяет маршрутизировать HTTP/HTTPS трафик через несколько агентов перед тем, как он достигнет origin сервера.

### Обычная маршрутизация (Direct)
```
Клиент → Агент → Origin Сервер
```

### Anycast маршрутизация
```
Клиент → Агент A → Агент B → Агент C → Origin Сервер
```

## Зачем это нужно?

### 🛡️ Многослойная защита от DDoS
Каждый агент в цепочке применяет:
- WAF (Web Application Firewall)
- Rate Limiting (ограничение запросов)
- Firewall правила
- IP блокировки

Атакующий трафик фильтруется на каждом уровне, что значительно повышает защиту.

### 🌍 Географическая оптимизация
Вы можете направить трафик через агенты, которые находятся ближе к вашему origin серверу, снижая задержку (latency).

### ⚖️ Распределение нагрузки
Трафик распределяется между несколькими агентами, что помогает балансировать нагрузку.

### 🔒 Глубокая защита (Defense in Depth)
Множественные слои проверки и фильтрации перед достижением вашего сервера.

## Как включить?

### Шаг 1: Откройте настройки домена

1. Перейдите в **Dashboard → Domains**
2. Выберите нужный домен
3. Откройте вкладку **"Anycast"**

### Шаг 2: Выберите режим маршрутизации

**Direct (по умолчанию):**
- Прямая маршрутизация на origin
- Работает как обычно

**Anycast (BETA):**
- Маршрутизация через пул агентов
- Требует настройки пула агентов

### Шаг 3: Настройте пул агентов

Нажмите **"Добавить агент"** и заполните:

#### Автоматический выбор
Выберите агент из списка существующих — поля заполнятся автоматически.

#### Ручная настройка

**ID агента:**
- Уникальный идентификатор агента
- Пример: `agent-eu-west`, `agent-us-east`

**Endpoint (URL):**
- Полный URL агента
- Пример: `https://agent-eu.example.com`
- Должен быть доступен по HTTPS

**Регион (опционально):**
- Географический регион агента
- Пример: `eu-west`, `us-east`, `asia`
- Используется для информации

**Приоритет:**
- Число от 0 до 100
- **0 = наивысший приоритет**
- Агенты с меньшим числом выбираются первыми
- Агенты с одинаковым приоритетом выбираются случайно

### Шаг 4: Настройте максимум хопов

**Максимум хопов (прыжков):**
- Сколько агентов может пройти запрос
- **Рекомендуется: 3**
- Предотвращает циклы маршрутизации
- Диапазон: 1-10

### Шаг 5: Сохраните изменения

Нажмите **"Сохранить"** в правом верхнем углу.

## Примеры конфигурации

### Пример 1: Простая цепочка

```
Режим: Anycast
Максимум хопов: 3

Агент 1:
  ID: agent-edge
  Endpoint: https://edge.example.com
  Приоритет: 0

Агент 2:
  ID: agent-filter
  Endpoint: https://filter.example.com
  Приоритет: 0
```

**Результат:**
```
Клиент → agent-edge → agent-filter → Origin
```

### Пример 2: С приоритетами

```
Режим: Anycast
Максимум хопов: 2

Агент 1 (основной):
  ID: agent-eu-primary
  Endpoint: https://eu-primary.example.com
  Приоритет: 0

Агент 2 (основной):
  ID: agent-us-primary
  Endpoint: https://us-primary.example.com
  Приоритет: 0

Агент 3 (резервный):
  ID: agent-backup
  Endpoint: https://backup.example.com
  Приоритет: 1
```

**Результат:**
- Сначала выбирается случайно между `agent-eu-primary` и `agent-us-primary` (приоритет 0)
- `agent-backup` используется только если агенты с приоритетом 0 недоступны
- Максимум 2 хопа, затем на origin

### Пример 3: Географическая цепочка

```
Режим: Anycast
Максимум хопов: 3

Агент 1:
  ID: agent-eu-west
  Endpoint: https://eu-west.example.com
  Регион: eu-west
  Приоритет: 0

Агент 2:
  ID: agent-eu-central
  Endpoint: https://eu-central.example.com
  Регион: eu-central
  Приоритет: 0

Агент 3:
  ID: agent-origin-region
  Endpoint: https://origin-region.example.com
  Регион: us-east
  Приоритет: 0
```

**Результат:**
Трафик проходит через несколько регионов перед достижением origin.

## Как это работает?

### 1. Клиент делает запрос
```
GET https://example.com/api/data
```

### 2. Первый агент (Edge)
- Применяет WAF, rate limiting, firewall
- Проверяет режим маршрутизации: `anycast`
- Проверяет количество хопов: 0
- Выбирает следующий агент из пула
- Добавляет заголовок: `X-Defenra-Hop: agent-edge-1234`
- Проксирует запрос на следующий агент

### 3. Второй агент (Filter)
- Применяет WAF, rate limiting, firewall
- Проверяет количество хопов: 1
- Выбирает следующий агент или origin
- Добавляет заголовок: `X-Defenra-Hop: agent-edge-1234,agent-filter-5678`
- Проксирует запрос

### 4. Достижение лимита хопов
Когда количество хопов >= `maxHops`, запрос идёт на origin.

### 5. Ответ возвращается
```
Origin → Агент B → Агент A → Клиент
```

## Мониторинг

### Логи агентов

Каждый агент логирует решения маршрутизации:

```
[HTTP] Routing decision: mode=anycast, target=https://agent-b.example.com, isAgent=true, hopCount=0, reason=selected agent agent-b from pool
[HTTP] Added hop header: agent-a-1234 (total hops: 1)
```

### Заголовок X-Defenra-Hop

Отслеживает полный путь маршрутизации:

```
X-Defenra-Hop: agent-edge-1234,agent-filter-5678,agent-final-9012
```

Показывает:
- Какие агенты обработали запрос
- В каком порядке
- Сколько хопов было сделано

### Метрики

Агенты собирают метрики:
- Количество запросов в режиме anycast
- Среднее количество хопов
- Fallback события (когда агент недоступен)
- Выбор агентов

## Безопасность

### Автоматический Fallback

Если агент недоступен:
1. Логируется предупреждение
2. Запрос автоматически идёт на origin
3. Клиент получает ответ (не видит ошибки)

### Предотвращение циклов

**Лимит хопов:**
- Жёсткое ограничение на количество прыжков
- По умолчанию: 3
- Предотвращает бесконечные циклы

**Заголовок X-Defenra-Hop:**
- Отслеживает путь
- Позволяет обнаружить циклы
- Используется для отладки

### Сохранение IP клиента

Оригинальный IP клиента сохраняется в заголовках:
- `X-Forwarded-For`
- `X-Real-IP`

Origin сервер видит реальный IP клиента, а не IP агента.

## BETA ограничения

⚠️ **Это BETA функция. Есть ограничения:**

### 1. Ручная настройка
- Нет автоматического обнаружения агентов
- Нужно вручную добавлять агенты в пул
- Нужно вручную обновлять endpoints

### 2. Простой алгоритм выбора
- Случайный выбор среди агентов с одинаковым приоритетом
- Нет учёта нагрузки агентов
- Нет учёта здоровья агентов
- Нет географической оптимизации

### 3. Нет мониторинга здоровья
- Агенты не проверяются на доступность
- Fallback происходит только при ошибке запроса
- Нет предварительной проверки

### 4. Нет аутентификации
- Агенты доверяют друг другу
- Нет проверки подлинности между агентами
- Полагается на безопасность сети

### 5. Производительность
- Не оптимизировано для скорости
- Каждый хоп добавляет задержку
- Фокус на корректности, не на производительности

## Устранение неполадок

### Проблема: Трафик не идёт через агенты

**Решение:**
1. Проверьте, что `routingMode` установлен в `anycast`
2. Убедитесь, что `agentPool` не пустой
3. Проверьте, что endpoints агентов доступны
4. Проверьте логи агентов

### Проблема: Циклы маршрутизации

**Решение:**
1. Проверьте `maxHops` (должен быть >= 1)
2. Проверьте заголовок `X-Defenra-Hop` в логах
3. Убедитесь, что агенты не ссылаются сами на себя в пуле

### Проблема: Агент недоступен

**Решение:**
1. Проверьте логи: должно быть "fallback to origin"
2. Проверьте endpoint агента (доступен ли по HTTPS?)
3. Проверьте сетевое соединение между агентами
4. Временно удалите недоступный агент из пула

### Проблема: Медленные ответы

**Решение:**
1. Уменьшите `maxHops` (меньше прыжков = быстрее)
2. Проверьте задержку между агентами
3. Используйте агенты ближе друг к другу географически
4. Рассмотрите возможность использования `direct` режима

## FAQ

### Можно ли использовать anycast для всех доменов?

Да, но рекомендуется начать с тестового домена и проверить производительность.

### Сколько агентов можно добавить в пул?

Технически неограниченно, но рекомендуется 2-5 агентов для оптимальной производительности.

### Работает ли anycast с GeoDNS?

Да! GeoDNS определяет, на какой агент попадёт клиент, а anycast определяет путь от этого агента до origin.

### Можно ли смешивать HTTP и HTTPS агенты?

Да, но рекомендуется использовать только HTTPS для безопасности.

### Что происходит, если все агенты в пуле недоступны?

Запрос автоматически идёт напрямую на origin (fallback).

### Влияет ли anycast на SSL сертификаты?

Нет, SSL терминация происходит на первом агенте, как обычно.

### Можно ли использовать anycast с Page Rules?

Да, Page Rules применяются на каждом агенте в цепочке.

### Как отключить anycast?

Измените `routingMode` обратно на `direct` и сохраните.
